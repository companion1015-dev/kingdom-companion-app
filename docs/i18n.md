# App language — how it works and how to extend it

Kingdom Companion can be shown in several languages. English is the source language. This guide is for whoever maintains the app.

## What users get
- **Pick a language** from the 🌐 button in the header, the *Profile → App language* row, or `/settings/language`.
- **It is remembered** on the device (cookie) and, when signed in, saved to the account — so it follows the user to another device.
- **One-time suggestion:** a first-time visitor whose device language is offered sees *“This app is available in your language”* (in that language). Never repeated, never forced.
- **Right-to-left** languages (Arabic, Urdu) flip the whole layout; the direction is set before first paint, so there is no flash.
- **Missing translations never break anything:** an untranslated text simply shows in English.
- **Scripture is never machine-translated.** Bible text must come from licensed Bible versions.

## Where things live
| What | File |
|---|---|
| List of languages, status, direction | `src/lib/i18n/config.ts` |
| One dictionary per language | `src/lib/i18n/messages/<code>.ts` |
| Lookup + formatting helpers | `src/lib/i18n/translate.ts`, `format.ts` |
| Provider, picker, suggestion | `src/components/i18n/` |
| Tools | `scripts/i18n.cjs` (`npm run i18n -- …`) |

## Everyday tasks
**Translate a new screen**
1. Write the screen in English as normal.
2. `npm run i18n -- wrap src/app/(app)/my-screen/page.tsx` — wraps visible text in `<T>…</T>` and lists texts that still need translating.
3. Add those texts to every file in `src/lib/i18n/messages/`.
4. `npm run i18n -- check` must say **OK**.

Rules for new code:
- Visible text: `<T>English text</T>`. Attributes (placeholder, aria-label, alt): `const tr = useTr()` then `tr('English text')`.
- **Never wrap Scripture or names.** Put `translate="no"` on the element and the tool skips it.
- A sentence split by a link or a value must be translated as one piece — use `tr('… {name} …')`-style whole sentences, not fragments.
- Dates/numbers/money: `formatDate`, `formatNumber`, `formatCurrency` from `@/lib/i18n` — never `toLocaleDateString()`.
- For right-to-left, prefer logical Tailwind classes (`ms-4`, `me-4`, `ps-`, `pe-`, `text-start`, `text-end`) over `ml-`/`mr-`/`text-left`.

**Add a language**
1. `npm run i18n -- new de "Deutsch" "German" ltr` (use `rtl` for right-to-left). The language is added as **hidden**.
2. `npm run i18n -- export` gives `i18n-review.csv` for translators; or fill `messages/de.ts` directly.
3. Set `status: 'beta'` in `config.ts` once it is complete and `npm run i18n -- check` is **OK**.
4. When a native speaker and (for religious text) a theological reviewer have approved it, set `status: 'live'`.

**Review translations**: `npm run i18n -- export` → send the CSV to native speakers → paste corrections back.

## Quality rules
- Translations are drafts until a native speaker has reviewed them. Keep the *beta* label until then.
- Religious terms differ between church traditions and regions — agree a glossary with the community before going live.
- Legal pages (Privacy, Terms) must be translated by qualified human translators.
- Translating **database content** (devotionals, reading plans, blog) and **Bible versions** is a separate system (stored translations with review status); do not machine-translate Scripture.
